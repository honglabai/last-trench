## 2. 특히 중요한 '최신 수정 사항' 우선순위

**인터뷰 Q10 변경 기록(반드시 최신 우선)**

| 항목 | 초기 선택(폐기) | 최종 선택(유효) |
|---|---|---|
| 시설 설치 | 혼합 설치(대형 지정+소형 자유) | **지정 슬롯에만 설치** |
| 적 출현 | 360도 다방향 출현 | **정면 중심 공격** |
| 맵 수 | 모드별 최초 1개 이후 확장 | 변경 없음 |
| 부분 파괴 | 일부 엄폐물 파괴 가능 | 변경 없음 |

Q09에서 사용자가 선택한 '여러 방향에서 동시 공격'은 Q10의 최종 **정면 중심**보다 먼저 확정되었다. 따라서 '상시 360도 스폰'은 **폐기**하고, 필요하면 **전방 좌/중/우 부채꼴 변주**나 '전방에서 들어오는 포격/드론 경고'처럼 정면 중심을 유지하는 **특수 이벤트**로 반영한다. 새로운 후방 공격 로직은 사용자 재승인 없이는 설계 범위에 포함하지 않는다.

## 3. 충돌로 보일 수 있는 규칙 정리

### 3.1 병사 사망 vs 1회 부활

Q08은 '병사 사망 또는 거점 상실 패배', Q17은 '1회 부활', Q21은 '즉시 자동 부활'을 확정했다. **통합 규칙:** 첫 병사 사망은 자동 부활 1회를 소모하고 전투 지속; 재사망 시 패배; 거점 파괴·점령은 부활 잔여와 무관하게 즉시 패배. 부활 사용 상태는 런 체크포인트에 포함한다.

### 3.2 오프라인 게임 vs 보상형 광고

Q18의 오프라인은 **핵심 게임 실행·저장·기록에 네트워크가 필요하지 않음**을 의미. 광고는 네트워크가 가용하고 사용자가 명시적으로 선택했을 때만 작동하는 선택 기능. 광고 네트워크 불능 시 경고/버튼 비활성화, 무광고 상태에서도 정상 진행 가능. 서버 기반 계정/온라인 랭킹은 기본 범위 밖.

### 3.3 게임 15웨이브 vs MVP 3웨이브

MVP1은 개발 검증용 첫 기능 범위. 최종 게임에는 **15웨이브**를 구현한다. MVP1에서 15웨이브나 모든 보스를 한 번에 구현하지 않는다. 게임 모드도 처음 참호 하나로 시작해 뒤에 개활지를 추가한다.

### 3.4 모바일 우선 vs Mac에서 개발

Mac은 **개발 컴퓨터**, Android는 **첫 실행 기기**다. Mac 에디터에서 키보드/마우스 테스트를 만들더라도 모바일 터치 UX를 최우선으로 두며, Mac 실험만으로 Android 성능 검증을 대체할 수 없다. iOS는 그 다음, PC 배포는 가장 후순위.

### 3.5 자동 그래픽 최적화 vs 사용자 그래픽 설정

첫 실행 시 기기 프로필을 감지해 저/중/고 후보 중 적절한 프로필을 제안. 사용자는 직접 재설정 가능. 실제 30FPS 성능은 기기 테스트로 판단한다.

### 3.6 웨이브 경계 자동 저장 vs 진행 중 게임 이어하기

앱을 닫더라도 '이어하기' 선택 가능하되, **마지막 웨이브 종료의 커밋 완료된 안전 체크포인트**에서 다시 시작한다. 전투 중 모든 총알 위치를 프레임 단위로 복원하는 기능은 요구하지 않는다. 결과를 종료/포기하면 active 런은 무효화.

### 3.7 영구 해금 vs 광고 보상

장비 해금은 웨이브+업적의 플레이 결과로 달성하며, 광고는 **선택적 보조 보상**이다. 광고를 시청해야만 해금 가능한 장비를 만들지 않는다.

## 6. 변경관리 규칙

- 이후 새로운 요청으로 Q##의 내용이 바뀌면, `docs/change_log.md`에 **기존값→신규값→일자→영향 파일**을 기록하고 Q##를 최신값으로 갱신.
- 에이전트가 '추천' 또는 '최적'이라는 이유로 **기존 확정 선택을 임의 변경하는 행위 금지**.
- 신규 기능은 `UX`, `TECH`, `BALANCE`, `POST-LAUNCH` 백로그로 구분. 필수 요구(Q##)와 별도로 관리.
- 기술적 불가능/SDK 제약을 발견하면 **근거/대안/사용자 승인**이 선행되어야만 범위를 변경할 수 있음.
- 구현·테스트가 미완료인 Q##는 '설계 확정, 구현 대기'로 표시한다.
