# 05. Google Antigravity — 단계별 실행용 바이브 코딩 프롬프트 전체 세트

**총 26개 독립 작업:** P00~P25. **각 프롬프트를 한 번에 하나만** Antigravity Agent에 복사한다. 04 마스터 프롬프트를 먼저 적용하고, 완료 후 사용자 테스트/승인을 거쳐 다음 단계로 진행한다. 에이전트가 `docs/*.md`를 읽을 수 있도록 이 패키지를 프로젝트의 docs 폴더에 복사해야 한다.

## 공통 프롬프트 규칙

- 인터뷰 21개 중 가장 최신 선택 우선: **지정 위치 설치만**, **적 정면 중심**, **두 독립 모드**, **Godot 4/GDScript/Antigravity/Mac/Android 우선**.
- 명령·테스트는 **실제로 실행한 것만** 통과로 기록. Android 실기기 없으면 실기기 테스트는 `NOT TESTED`.
- 매 단계에서 코드를 쓰기 전 변경 파일과 설계부터 제시; 단계별 변경 범위 이탈 시 먼저 승인 요청.
- 자동 수정 후 Godot 헤드리스 임포트·씬 실행·유닛 테스트를 실행하고 로그 보고.
- 단계 실패 시 `04`의 오류 복구 프롬프트로 수정. 현재 Gate를 넘지 않고 다른 단계 기능을 추가하지 않는다.

## P00. Mac 개발 환경·버전 잠금

**단계:** 사전/환경 | **선행 Gate:** 없음

### Antigravity에 복사할 프롬프트

```text
[LAST TRENCH / P00: Mac 개발 환경·버전 잠금]
04_Antigravity_Master_Prompt.md의 불변 조건을 모두 따르라.
선행 단계: 없음. 선행 Gate가 통과되지 않았다면 먼저 부족한 항목만 보고하고 새 코딩을 시작하지 말 것.

목표/구현 지침:
실제 Mac 개발 환경에서 Godot 4 Standard(GDScript), Google Antigravity, Git, Android Debug Bridge 설치 여부를 확인하고, Godot 버전과 실행 경로를 기록한다. Godot 4 안정 버전을 선택하고 무단 업그레이드를 방지한다. Mac ARM/Intel 여부 및 SDK가 없어도 Godot 로컬 작업을 시작할 수 있게 구분한다.

예상 파일·구현 범위:
docs/dev_environment.md 생성, 현재 PATH·실행 가능한 Godot 명령을 기록. 별도의 비밀값은 기록하지 않는다. Godot 없으면 설치 안내를 작성하고 BLOCKED 처리.

필수 테스트/완료 판정:
godot --version 혹은 실제 .app 실행 경로로 동일 검증; godot --help 반환 확인. SDK 미설치면 Android 빌드는 준비중으로 표기.

작업하기 전에 수정 파일 목록/의존성/테스트 계획을 제시하라. 파일을 직접 작성한 뒤 실제 Godot 명령을 실행하고 로그를 남겨라.
GDScript 문법/씬 참조/상태 신호/Android용 가로 화면 제약을 유지하라. 구현되지 않은 것은 구현 완료로 보고하지 말 것.
단계 결과를 PASS/FAIL/BLOCKED로 보고하고, 파일별 변경 내역·사용자 실기기 확인 항목·되돌리는 방법을 기록하라.
다음 P번호는 사용자 승인 전 실행하지 말 것.
```

**Gate(요약):** godot --version 혹은 실제 .app 실행 경로로 동일 검증; godot --help 반환 확인. SDK 미설치면 Android 빌드는 준비중으로 표기.

```text
단계 결과를 PASS/FAIL/BLOCKED로 보고하고, 파일별 변경 내역·사용자 실기기 확인 항목·되돌리는 방법을 기록하라.
다음 P번호는 사용자 승인 전 실행하지 말 것.
```

**Gate(요약):** 최종 수락표에 PASS/FAIL/NOT TESTED 구분, 실행·실기기 증거. 서명키·개인정보·재현 불가 결함 문제 남으면 출시 금지.

## 보조 운영 절차

### 각 단계 직후 사용자에게 확인할 것

1. **프로젝트 실행:** Godot 에디터에서 `project.godot`을 열고 시작 씬에 오류가 없는지 확인한다.
2. **기능 동작:** 프롬프트의 Gate에 해당하는 UI/전투 흐름을 직접 재현한다.
3. **로그 확보:** Godot Output/Debugger, Antigravity 터미널 실행 결과, 기기 Android 로그를 단계 문서에 기록한다.
4. **커밋/백업:** 통과 시 Git 커밋 또는 사용자 승인 백업을 만든다.
5. **다음 단계:** 실패한 기능이 있으면 우선 고치고 테스트한다. P##을 건너뛰지 않는다.

### 공통 프롬프트: 단계 진행 재개

```text
LAST TRENCH 작업을 이어서 진행하라. 현재 Git 상태, 마지막 PASS Gate 번호, 남은 실패 테스트를 읽어라. 기존 요구사항 추적표를 우선 적용하고, 마지막 PASS 이후의 변경만 분석하라. 내가 다음 P번호를 지정하기 전에는 새로운 기능을 추가하지 말고 현재 오류와 증빙을 정리하라.
```

### 공통 프롬프트: 테스트 증거 요청

```text
현재 단계에 대해 작성했다고 주장한 파일을 실제로 찾고, Godot 파싱/임포트/씬 실행 테스트를 재수행하라. 실행한 명령, 종료코드, 핵심 로그, 미실행 테스트, 실패 원인을 그대로 기록하라. Android 실기기 없이 FPS 30 달성 또는 터치 정상이라고 단정하지 말 것.
```

### 다음 단계로 넘어가지 말아야 할 경우

- Autoload 경로 또는 `.tscn` 씬 파일에 오류가 남아 있음.
- `--headless --editor --import` 명령이 오류를 반환했는데 무시한 상태.
- 요구사항의 **정면 스폰·고정 슬롯·독립 모드**를 위반하는 새로운 기능이 포함됨.
- 저장·보상 시스템에서 중복 지급 또는 데이터 유실 사례가 미해결.
- Android에서 직접 확인이 필요한 Gate를 실기기 없이 PASS 표시.

**주의:** 이 문서는 사용자 Mac에서 Antigravity 에이전트가 코드를 작성하도록 하는 지시문 세트이며, 이미 게임이 코딩되었다는 뜻이 아니다.
