# 02. 개발 실행계획서 — LAST TRENCH

**버전:** 1.0 | **개발 방식:** Mac + Godot 4/GDScript + Google Antigravity | **원칙:** 1단계 구현→실제 검증→사용자 승인→다음 단계

## 1. 목표와 작업 경계

최종 제품은 **참호/개활지 독립 모드**, 3인칭 3D, Android 우선, 15웨이브/20~30분, 5·10·15 보스, 이중 재화·무기/시설 성장·기록·설정·2개 언어·보상형 광고다. 그러나 이를 **하나의 프롬프트로 한 번에 코딩하지 않는다**. 첫 목표는 Android에서 3웨이브를 완주하는 플레이 가능한 MVP1이며, 그 완료를 확인한 뒤 MVP2, 완성형, 출시 기능을 추가한다.

- 스프린트는 시간 고정이 아니라 **작동하는 결과물과 Gate**를 기준으로 관리한다.
- 에이전트가 작성한 코드는 반드시 실제 Godot 실행, 문법 검사, 터치·게임 동작 확인을 거친다.
- 모든 단계는 Git 커밋 가능 단위로 구성한다. 실패한 실험은 다음 단계로 이어지지 않게 분리한다.
- 외부 에셋은 초기에는 사용하지 않고 MeshInstance3D, PrimitiveMesh, BoxMesh 등으로 모델/참호를 자동 생성한다.
- Android 물리적 기기가 없는 에이전트 환경에서는 **실기기 통과를 주장하지 않는다**. 사용자의 직접 확인이 필요하다.

## 3. MVP1 상세 작업 패키지

### 3.1 기능 범위(고정)

- **환경:** 참호 1개, 전방 적 출현, 파손 가능한 모래주머니 일부, 지정 방어시설 슬롯 1개 이상. 실제 맵은 Godot 코드가 프리미티브 메시로 구성.
- **플레이어:** 병사 1명, 소총 1종, 3인칭 이동/시야, ADS 어깨너머, 사격/피격/재장전. 조준 보조 강도 설정 진입점.
- **적군:** 보병 1종(지상 이동·사격·거점 공격), 공격 드론 1종(전방 하늘 경로·공격), 각각 시각 구분과 피격 체계.
- **방어시설:** 기관총 포탑 1종, 가까이 접근 시 설치·수리 버튼, 자동 공격/체력/피해 적용.
- **게임 상태:** 3웨이브, 적 수 제한, 중간 휴식, 승패, 즉시 부활 1회, 거점 상실 패배.
- **HUD:** 체력·탄약·웨이브·거점 체력·적 경보·시설 상태·터치 버튼. 경제 미구현 단계에서는 표시 영역/인터페이스만 준비 가능.

### 3.2 MVP1 실기기 승인 시나리오

1. Android 가로 방향으로 열리고 메뉴에서 '전투 시작'을 탭한다.
2. 왼쪽 스틱으로 이동하고 오른쪽 화면을 밀어 시야가 움직인다. ADS 시 어깨너머로 바뀐다.
3. 보병을 쏘면 체력이 감소하고 처치된다. 탄약이 소진되면 재장전이 필요하다.
4. 드론이 **전방 상공**에서 접근하여 피해를 입히고, 소총 또는 시설의 규칙에 따라 격파 가능하다.
5. 정해진 슬롯에 다가가 기관총 포탑을 설치·수리할 수 있으며, 다른 위치에는 설치할 수 없다.
6. 플레이어 첫 사망 후 즉시 부활한다. 다시 죽거나 거점이 상실되면 패배.
7. 3웨이브 모두 격퇴하면 승리 화면을 볼 수 있다.
8. 플레이 동안 앱 강제 종료·화면 전환·터치 입력 중복으로 크래시하지 않는지 확인한다.

### 3.3 MVP1 완료 판정

- 필수 시나리오 1~7에서 **심각도 S0/S1 버그 0건**.
- 테스트 로그에 사용 기기 모델, Android 버전, Godot 버전, 빌드 ID 기록.
- FPS는 계측하며 30FPS는 최종 최적화 목표. 초기 MVP에서 미달할 경우 원인과 개선 백로그를 남겨 단계 통과를 사용자 승인으로 결정.

## 4. MVP2 상세 작업 패키지

### 4.1 경제와 강화

**Credits:** 무기 구매·강화. **Supplies:** 탄약·포탑 설치·수리. 매개변수는 JSON/Resource 데이터로 조정한다. 웨이브 완료 시 크레딧 추가 보상과 랜덤 강화 카드 3중 1을 처리한다. 재접속/더블 탭/네트워크 상태와 무관하게 **보상 거래는 한 번만**.

### 4.2 영구 진행

장비 해금·업적·최고 기록은 `profile.json`, 진행 중 전투는 `active_run.json`으로 구분. 영구 데이터에 런 크레딧을 기록하지 않는다. 전투 종료/포기 시 active_run을 무효화하되 프로필은 보존.

### 4.3 체크포인트

웨이브 전투 도중 앱 종료 시 **마지막 정상 저장된 웨이브 경계**부터 재개. 최초 시작 전 저장이 없다면 안전한 출격 초기 상태에서 시작. 카드 보상과 체크포인트 커밋을 하나의 상태 전이로 처리하여 보상 중복 방지.

### 4.4 결과화면 및 메인 메뉴

게임 시작, 이어하기/포기, 장비고, 업적, 전투 기록, 설정. MVP2에서는 아직 구현되지 않은 화면도 오작동 버튼 대신 명확한 '준비 중' 상태로 다룬다.

## 5. 완성형 확장 상세 작업

- **15웨이브:** 1~4 적응, 5 보스, 6~9 복합, 10 보스, 11~14 고난도, 15 최종 공세. 전투 목표 시간 20~30분.
- **공격 유형:** 보병·드론 외 RPG·전투로봇·정찰·포격·방사포·헬기·전투기 위협을 역할별로 추가. 직접 캐릭터가 필요하지 않은 화력 위협은 경보 이벤트형으로 구현하여 성능 유지.
- **보스:** 드론 지휘체(5), 중장갑 전투로봇(10), 최종 복합 공격(15). 공격헬기와 대규모 포격도 추가 보스/특수 이벤트 풀에 포함.
- **AI 적응:** 방어시설/전투 성과 기반 사전 정의된 프리셋 변형. 고정 보스·전방 중심·난이도 상한 유지.
- **개활지:** 참호 씬과 별도 전장 씬. 공통 `GameSession`/`Player`/`Enemy` 인터페이스를 재사용. 모드 전환은 메인 메뉴에서만.
- **장비·UI:** 7계열 무기/장비, 세 난이도, 조작/사운드/색상/언어 설정, 한국어·영어 동시.
- **후속:** 무한 생존은 정식 핵심 기능 완료 후 별도 확장. 이 MVP 범위에 넣지 않는다.

## 6. 출시 준비 및 운영

### 6.1 모바일 빌드

- Android 디버그 APK 실기기 반복 설치 → 내부 테스트 → 서명 AAB → Google Play 제출.
- iOS는 Android 완성 후 macOS Xcode와 실제 iPhone 테스트로 확장.
- PC는 키보드/마우스 입력 어댑터와 해상도/UI 대응을 완료한 다음 빌드.

### 6.2 보상형 광고

- 최초 MVP1/2에서는 광고 의존 0. 출시 단계에서 Godot 4와 현재 Android API에 호환되는 광고 플러그인 검증.
- **광고 없는 오프라인 게임을 불변 기능**으로 보장. 선택형 버튼은 인터넷/광고 재고가 없으면 비활성/대체 안내. `RewardedAdProvider` 인터페이스 뒤에 광고 SDK를 격리.
- 광고 보상은 **시청 완료 검증 후 1회** 지급. 실패·중복 콜백·앱 중단·비정상 광고 로딩을 테스트.
- 무료 개발 도구/에셋 정책과 스토어 개발자 등록비·서명·광고 운용비가 0원이라는 뜻은 다르며, 비용 발생 전 사용자 승인 필요.

### 6.3 이용자 경험/정책

- 한국어·영어 텍스트 누락 0, 터치 영역 충돌 0, 실제 주요 화면의 접근성 점검.
- 사생활·데이터 수집/광고 관련 정책 및 스토어 콘텐츠 등급은 **출시 당시** 공식 요건 검토.
- 외부 3D/음원 에셋을 추가할 경우 라이선스 증빙을 `licenses/`에 보관.

## 7. 역할과 승인 규칙

| 역할 | 책임 |
|---|---|
| 사용자(Product Owner) | 게임 요구사항 최종 승인, 실기기 체험, 기능·밸런스 피드백, 키/계정 관리 |
| Antigravity 에이전트 | 코드·씬 생성/수정, 로컬 테스트 실행, 로그 분석, 패치 제안, 변경 내역 기록 |
| Godot 에디터/CLI | 씬 실행, GDScript 파싱/리소스 임포트, 디버그 빌드 |

**에이전트가 자동 승인하지 않는 항목:** 저장 데이터 파괴, 코드 전체 재작성, 라이선스 추가, 유료 서비스 사용, 서명키 취급, 광고 SDK 도입, 외부 공개/스토어 제출.

## 10. 결함 분류와 출고 금지선

- **S0:** 기기 강제 종료/저장 손상/보안 유출 → 즉시 출고 금지.
- **S1:** 승패 불가, 버튼 동작 불능, 복구 불가, 광고 강제 → 출고 금지.
